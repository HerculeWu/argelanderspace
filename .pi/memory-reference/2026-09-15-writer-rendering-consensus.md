## 1. 核心意图

**编辑器采用成熟依赖；渲染复用已有主干，而不是另造一套。**

ArgelanderSpace 已有“源码 → latexmk 编译 → 编译事实与源码 AST 融合 → IR → 消费 IR 展示”的文献浏览管线。Writer 应复用其已有模块与能力，再增加写作场景所需的适配。

用户对该方向明确表示：**“这一直是我想要的。”** 这不是因其他方案失败才临时妥协，而是本轮架构选择的首要意图。

本共识不把稿件变成文献库条目，不增加 PDF 预览，不将自研补全或完整 IDE 作为目标。

## 2. 编辑器：复用成熟组件，不为功能清单自研

来源：Q2、Q4；inbox D2、D4。

采用以下基线方向：

- **CodeMirror 6** 编辑器；
- **`@uiw/react-codemirror`** React 包装；
- **`@codemirror/legacy-modes` 的 `stex`** LaTeX 高亮。

替换当前 textarea 与高亮 pre 叠层方案，优先解决编辑、高亮、光标和输入体验。不能因为库有相关机制，就在未经真实浏览器验证前宣称本项目所有 IME、换行、滚动问题已经解决。

编辑辅助以现成方案实际能力为准：

- 启用适用的现成能力；
- **不为凑齐命令、文献 key、label 等补全清单而自研系统**；
- `stex` 是高亮模式，不自带完整 LaTeX 语义补全；
- CodeMirror 的补全菜单、筛选与 snippet 机制，不等于已经接通本项目文献库和稿件上下文；需要适配的能力必须单独说明，不能包装成“零代码开箱即用”。

本次仅确定选型方向，未安装依赖或钉定版本。后续锁定版本时仍须核查依赖、许可证与运行兼容性。

## 3. 渲染主线：共享编译、解析、融合与 IR 展示能力

来源：Q5、Q13；inbox D5、D13。**Q13 替代曾在 Q12 考虑的 TeX4ht 默认路线。**

```text
Writer cells + 模板 + bibliography + 资产
                     │
                     ▼
          Writer 输入组装与位置映射
                     │
                     ▼
           共享 latexmk 编译能力
                     │
                     ▼
           编译事实 + 源码 AST
                     │
                     ▼
              共享 IR 融合
                     │
                     ▼
         Writer cell／展示上下文适配
                     │
                     ▼
               cell 流式预览
```

### 3.1 应复用与应适配的边界

应优先复用现有编译基础设施、插桩、facts 解析、源码解析、IR 融合、数学与段展示能力；不是复制一套 Writer 专属管线再分别维护。

Writer 需要的适配包括：

- 将稿件 cells、模板、bibliography 和资产组装为编译输入；
- 保留源码位置、IR 块与 cell 的对应关系；
- 管理连续编辑下的编译缓存、调度和结果新鲜度；
- 为现有段展示能力提供 Writer 的引用、导航与交互上下文；
- 补齐本共识约定范围内的引用语义。

“复用”不表示现有函数、组件都能零改动直接调用。具体共享接口、源码映射载体、缓存键与模块拆分应在实施方案中确定；本共识不预先钉死其 API。

### 3.2 不复用的外层副作用

Writer 稿件仍独立于 work/doc 和文献库。不得因复用底层管线而自动引入：

- 摄入身份归并、文献库重建或将稿件入库；
- 文献 doc 的标注、归档或删除生命周期；
- 对既有 CLI 输出的行为变更。

保持 reader 既有默认行为及 CLI 冻结输出。共享模块的改进应通过必要的显式适配或隔离实现，不以“代码复用”为由顺带改变这些契约。其余硬约束继续遵循[契约与决策](../memory/contracts-and-decisions.md)。

### 3.3 不引入额外转换主线

**本阶段默认不新增 TeX4ht／make4ht 运行依赖，也不以 PDF 预览替代 cell 预览。**

TeX4ht 调研证明了其在合成稿中处理 natbib 的可行性，但不能据此认定现有 IR 管线不可复用或必须被替代。相关探针仅保留为历史参考。

只有复用方案出现**具体、已有证据且难以合理解决的缺口**时，才重新向用户讨论外部转换器；不得自动切换路线。

## 4. 显示目标：语义与编号求真，不复制 PDF 版式

来源：Q6、Q9；inbox D6、D9。

### 4.1 保真范围

- 引用内容与格式遵循所用模板及编译结果；
- 章节、公式、图表编号使用编译真值，不在前端另行分配一套序号；
- `\citep`、`\citet`、`\ref`、`\eqref` 等命令保留各自含义，不一律压成裸 key 芯片；
- 正文继续采用 cell 流式布局，**不追求 PDF 的分页、栏宽、字体或像素级排版还原**。

保留现有 KaTeX 方向。现有库可显示显式 tag，阅读器也已有公式编号与数学分离展示的能力；不能因当前 Writer 未接编号，就推断必须更换数学库。具体编号如何进入数学／块展示留给实施方案，不允许由浏览器另数一套号冒充 TeX 真值。

### 4.2 第一轮兼容边界

先围绕**现有模板及其常规写法**完整验证，包括 natbib：

- 作者—年与数字模式；
- 多 key 引用；
- 可选参数、前后注；
- 星号变体及其作者显示差异。

保留扩展能力，但本阶段不承诺 BibLaTeX、自定义宏或任意外部模板全部兼容。遇到不支持的情况必须明确暴露，不能静默给出错误显示。

### 4.3 已知复用缺口，不应误作“全部现成”

现有源码 AST 已识别引用命令族、星号、可选参数及 key；融合层也已有命令模式、前后注与多 key 处理。但现有 reader 引用文本仍有作者—年重建的限制，尚未完整覆盖模板标点、数字模式和星号全作者。

因此本路线是**复用既有能力并补缺**，不是声称简单接线即可满足全部保真目标。精确引用效果必须与编译结果对照验证；这项必要适配不等于重新建设整套渲染主干。

## 5. 自动更新、缓存与失败体验

来源：Q1、Q5、Q7、Q8；inbox D1、D5、D7、D8。

### 5.1 编译调度

- Texifier 仅作性能／可行性参照，不代表本阶段增加 PDF 视图；
- 放开 Stage 10 的单遍 pdflatex 限制，由 **latexmk 按需运行文献处理与必要的多遍编译**；
- 正确性优先，复用中间产物，避免无谓重编译；
- 停止输入并保存后自动编译，Render 可立即请求刷新；
- 连续修改合并，编译期间仍可编辑，只补跑最新状态，不把每个中间版本都排队；
- 防抖时间和性能目标通过实测确定，不将小型合成探针耗时当实际 Writer 或大稿的延迟承诺。

### 5.2 陈旧与失败结果

- 编译不阻塞输入和保存；
- 对能够证明与当前内容／目标对应的旧结果，可以保留显示并明确标陈旧；
- 新增或结构已变化的位置显示未解析占位，**不得把旧编号套到新公式或其他新目标上**；
- 相同 label key 或旧的环境序号本身，不足以证明对应关系仍有效；
- 编译失败提供可查看的错误，不清空稿件、不伪装更新成功。

缓存、编译结果与当前稿件的关联校验，应服务于这些体验和数据保护边界，而不是为了“立即有数字”放宽正确性。

## 6. 插入行为与模板依赖

来源：Q10、Q11；inbox D10、D11。

### 6.1 右栏插入

- References 点击后只插入裸 cite key；
- Crossrefs 只插入裸 label；
- 不自动包成 `\cite{...}`／`\eqref{...}`，也不根据光标位置猜测命令；
- 命令由用户输入或使用现成编辑器能力。

这是对 Stage 10“References 插入完整 cite 命令”的明确修订，不是继续维持原行为。

### 6.2 缺少模板依赖

本机缺少模板所需 `.cls`、`.sty`、`.bst` 时：

- 继续允许编辑、保存和导出源码；
- 明确提示预览未完成以及具体缺项；
- 不偷偷换模板、文档类或引用样式；
- 导出源码必须提示依赖缺失，不能声称已经验证可编译；
- 依赖可由用户或 agent 在本机补齐，许可未核清的文件不随 npm 包分发。

## 7. MIT 发布边界

项目自有代码继续按 MIT 发布。所选 CodeMirror 核心相关包、stex 所在官方包及 React 包装的许可证已做原文核查；具体最终版本和传递依赖仍须在实际引入时检查。

依赖不必全部叫 MIT，但必须满足各自许可证义务。随包发布、打包内联与调用用户本机独立安装工具是不同情形，不能混为一谈：

- 保留应有的第三方版权、许可证及必要声明；
- 不把第三方文件一律重新标成 MIT；
- 不默认内联当前声明为 AGPL 的 LaTeX 扩展；
- 许可未核清的模板资源不随包分发。

这是一项发布边界，不是对所有候选、所有版本或所有组合分发方式作法律保证。

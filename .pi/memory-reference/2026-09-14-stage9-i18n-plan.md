- 状态：**已关闭**（2026-09-14 用户"开工"批准并授权实施；M1–M4 完成，四门全绿，真实浏览器验证 7/7；用户 smoke 通过并授权 commit/push）
- 编制：2026-09-14；基线 main@3e50860（工作区干净）
- 共识来源：[session inbox](../inbox/2026-09-14-stage9-i18n-grilling.md) D1–D5（grilling Q1–Q17，用户四轮确认 + 最终"确认"）
- 本方案获批准且用户明确授权实施前，不动任何代码。

## 1. 目标与非目标

**目标**
1. `packages/web` 全部用户可见文案集中到 `src/locales/` 的 JSON 配置文件（zh-CN 为唯一文案真相源）。
2. 交付可用的 zh-CN / en 即时切换，入口在 TweaksPopover（外观设置）。
3. 为后续多语言与文案打磨建立结构与规范。

**非目标（本阶段明确不做）**
- zh-CN 文案的任何改写/打磨/风格统一（零行为变化搬迁；~20 条英文残留、中英混排原样保留）。
- server `detail`/`job.error` 的中文化或错误码化（web 端现有改写逻辑原样迁移，透传路径不动）。
- CLI 输出（冻结契约）。
- 浏览器语言自动检测、语言偏好的 config.toml 化。
- 多于 zh/en 的其他语言。

## 2. 技术选型（共识已定，不再开放）

- 依赖：`i18next@^26.4.2`、`react-i18next@^17.0.14`（均 MIT，peer 兼容已核实）。不引入 languagedetector / http-backend。
- 文案载体：`packages/web/src/locales/zh-CN.json`、`en.json`（纯 JSON，每语言单文件，不用 namespace 拆分）。
- 模块：`src/i18n.ts`（初始化 + 导出实例）；`src/i18next.d.ts`（类型增强，以 zh-CN.json 为 key 源，key 拼错与插值变量漏传均编译报错）。
- key 规范：按域嵌套 + 英文语义 camelCase 叶子，嵌套深度 ≤3。域根沿用代码目录语义：`shell` / `components` / `doc` / `annotation` / `library` / `plan` / `common`。
- 插值：`{{var}}` 命名占位，整句一个 key；条件分支（含嵌套三元）拆独立 key，逻辑留代码。

## 3. 文件布局与模块设计

新增文件：

```text
packages/web/src/locales/zh-CN.json     # 唯一文案真相源
packages/web/src/locales/en.json        # 英文文案（M3 填充）
packages/web/src/i18n.ts                # 初始化模块
packages/web/src/i18next.d.ts           # CustomTypeOptions 类型增强
packages/web/tests/setup.ts             # 测试 setup：import "../src/i18n"
packages/web/tests/no-hardcoded-copy.test.ts  # 中文硬编码扫描（M1 建，白名单随迁移收缩）
packages/web/tests/locale-parity.test.ts      # zh/en key 对拍（M3 建）
```

修改文件：`package.json`（+2 依赖）、`src/main.tsx`（`import "./i18n"`，在 App 之前）、`vitest.config.ts`（`setupFiles: ["./tests/setup.ts"]`）、`index.html`（`lang="zh-CN"`，M4）、`src/argelander/theme.ts`（Tweaks 加 `language` 字段）、`src/argelander/TweaksPopover.tsx`（语言段，M3）、涉文案的 31 个 ts/tsx（M2 逐域）。

`i18n.ts` 要点：

```ts
import i18n from "i18next";
import { initReactI18next } from "react-i18next";
import zhCN from "./locales/zh-CN.json";
import en from "./locales/en.json";

// 与 theme.ts 同一 localStorage key 读取初始语言；默认 zh-CN，无浏览器检测
i18n.use(initReactI18next).init({
  resources: { "zh-CN": { translation: zhCN }, en: { translation: en } },
  lng: initialLanguage(),        // 读 argelander.tweaks 的 language 字段，非法值回退 zh-CN
  fallbackLng: "zh-CN",
  interpolation: { escapeValue: false },  // React 已转义
  returnNull: false,
});
export default i18n;
```

`i18next.d.ts` 要点：`declare module "i18next" { interface CustomTypeOptions { defaultNS: "translation"; resources: { translation: typeof zhCN } } }`（augmentation 目标模块名以 i18next 26 官方文档为准，实施时验证；若 react-i18next 17 有更新的推荐写法随之调整并在验收中说明）。

## 4. 迁移规则（M2 逐域适用）

1. **纯文案**：JSX 文本、按钮、标题、空状态、placeholder、title、aria-label、toast、确认框 → `t("<域>.<语义名>")`；组件内用 `useTranslation()`，非组件模块（model.ts/theme.ts/api 层）直接 import i18n 实例的 `t`。
2. **插值**：`` `上传失败：${job.error}` `` → `t("library.upload.failed", { error: job.error })`，JSON 值 `"上传失败：{{error}}"`。server 来的字符串只作变量透传，不进 JSON。
3. **条件文案**：`{copied ? "已复制" : "复制"}` → 两个 key（`copied` / `copy`），代码侧三元保留。
4. **枚举映射**：`STATUS_LABEL` 等迁入 JSON（`plan.status.todo` 等嵌套对象）；代码侧改为**渲染期取值**的类型化函数/映射（`statusLabel(s): Record` 语义不变，因语言可切换，不得是初始化时算一次的模块常量）。`theme.ts` 的强调色名（深空蓝…）同规则。
5. **日期**：`fmtDate` 与 `timelineScale` 月度刻度改 Intl：`zh-CN` → `month:"long", day:"numeric"`（输出须与现 `M月D日`/`2026年9月` **逐字节一致**，加单测钉死）；`en` → `month:"short", day:"numeric"`（`Sep 14` / `Sep 2026`）。按当前 i18n.language 分派。
6. **server detail/job.error 透传**：不改写、不入 JSON；web 端已有的改写分支（如 409→"文档正在摄入，请稍后删除"）是 web 文案，正常入 JSON。
7. **JSON 格式**：2 空格缩进、key 按域内语义分组排序；biome 对 `packages/web/**` formatter 已关，格式由本规范人工保持一致。

## 5. 语言切换（M3）

- `Tweaks` 增加 `language: "zh-CN" | "en"`，`DEFAULTS.language = "zh-CN"`；旧 localStorage 数据无此字段时由 load 的 `{...DEFAULTS, ...parsed}` 自然补默认。
- `TweaksPopover` 新增一组分段按钮"语言 / Language"：`中文` / `English`，复用 `tweak-seg` 样式；段标题与按钮文案自身也走 `t()`。
- `set("language", v)` 时（在 useTweaks 的 effect 或 Shell 接线处）调 `i18n.changeLanguage(v)` 并把 `<html lang>` 设为对应值；切换即时生效不刷新。
- index.html 静态 `lang` 改为 `zh-CN`（M4）；运行时切换由上述同步覆盖。

## 6. en.json 翻译规范

- 术语表（共识已确认）：计划 Plan / 任务 Task / 文献 Literature / 文献库 Library / 标注 Annotation / 引用 References / 文档 Document / 工作台 Workbench / 今日聚焦 Today / 已逾期 Overdue / 今天到期 Due today / 明天到期 Due tomorrow / 待办 To do / 进行中 In progress / 受阻 Blocked / 完成 Done。实施中遇到表外术语，按同风格补充并在交付说明中列出。
- 风格：sentence case；按钮动词开头；省略号沿用 `…`；zh 的中英混排（如 `文献工作台 · Literature`）在 en 只留英文部分；zh 的英文残留（如 `Go to in document`）在 en 保持相同英文。
- en.json 由 agent 起草全套，用户在 smoke 整体审校；不作为冻结契约，后续打磨阶段可修订。

## 7. 测试策略

1. **现有测试零改动**：12 个按中文文本断言的测试文件原样保留；测试环境默认语言 zh-CN（setup.ts import i18n 即得），全绿即"零行为变化"的回归证据。
2. **中文硬编码扫描**（`tests/no-hardcoded-copy.test.ts`）：递归读 `src/**/*.{ts,tsx}`（经 node fs，不走 glob 库），命中 `[\u4e00-\u9fff]` 且文件不在白名单则失败，报错带 文件:行号。M1 白名单 = 31 个涉文案文件全量；M2 每迁完一域即从白名单移除对应文件；M4 结束白名单为空。`src/locales/` 是 .json 不在扫描范围。
3. **zh/en key 对拍**（`tests/locale-parity.test.ts`，M3）：递归比较两 JSON key 集合相等、en 无空串、每个 key 的 `{{var}}` 变量集合一致。
4. **日期恒等**：zh 输出与现格式逐字节一致的单测（如 `fmtDate("2026-09-14") === "9月14日"`、月度刻度 `2026年9月`）。
5. 门禁：每里程碑结束跑四门 `corepack pnpm -r build / -r test / -r typecheck / lint`。

## 10. 风险与备注

- i18next 26 类型增强的准确写法以实施时官方文档验证为准；若增强失效，退化方案为 key 纯字符串 + 对拍测试兜底（须向用户说明）。
- happy-dom 提供 localStorage，测试环境语言隔离依赖 vitest 每文件独立环境；若有跨用例污染再补 reset。
- `i18n.ts` 被 model.ts 等非 React 模块 import，注意保持其无 React 依赖路径的循环导入清洁（i18n.ts 自身不 import 任何域模块）。
- 搬迁 diff 总量约 31 文件；M2 按域分批以便逐批审查"纯搬迁"属性。
- 本方案不改变任何数据契约、API、CLI 行为；不涉及 literatures/ 用户数据。

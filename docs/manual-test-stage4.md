# Stage 4 手动验收指南（计划页面）

本指南验证 Stage 4 的全部交互路径：landing 默认进计划页、空态引导、计划/任务 CRUD（弹窗复用）、
任务创建（弹窗唯一入口、due 必填）、状态流转、拖拽调序（列表组内/看板跨列）、今日聚焦、
时间线、任务抽屉（关联文档 / markdown+数学备注 / 删除撤销）、持久化与同步
（plans.json 落盘、外部改写免 F5、409 乐观锁、加载失败态）。每一步给出：
**要做什么**、**应该发生什么**、**出现什么说明有 bug**。

> 约定：下文 CLI 一律写 `node packages/app/dist/bin.js`（repo 内的打包产物），在 **repo 根目录**运行。
> 计划数据存在 **`status/plans.json`**——`status/` 永远与生效的 literatures **平级**（默认 `./status/`，
> `--data-dir` 指别处时与其平级）。格式 = 2 空格 pretty-print（agent 可读/git diff 友好）。
> **pandoc shim 与本手册无关**：它只影响 LaTeX 摄入与 golden 测试，计划页不摄入任何东西。
> Stage 3/3.1 的验收指南留档作回归参照（`manual-test-stage3.md` / `manual-test-stage3.1.md`）。

文中标 **（已预实测）** 的条目，是写本手册前在 8127 端口真实起服务跑过的验证（命令与结果附在 §0c）。

> ⚠️ **本节为开发侧已预实测记录，可整体跳过**——smoke 只需从 §1 开始。
> 如需逐条复现：先跑
> `node packages/app/dist/bin.js serve --port 8127 --data-dir /tmp/ms4-smoke/literatures`，
> 再逐条执行 curl。

以下均为本次编写前的真实执行结果，作为后文对应步骤的"已预实测"依据：

1. `GET /api/plans`（plans.json 不存在）→ `{"version":1,"rev":0,"plans":[]}`（空文档，不 404）。
2. PUT 合法文档（rev 0）→ **200**，响应体 rev 自增为 1；再次 GET 原样返回该文档。
3. PUT 携带过期 rev（0 ≠ 当前 1）→ **409 `{"detail":"rev mismatch","rev":1}`**（回传当前 rev）。
4. PUT schema 非法（`version: 2`）→ **400 `{"detail":"request body is not a valid plans document"}`**。
5. SPA fallback：`GET /` 与 `GET /doc/arxiv-2501.17225` 均返回 index.html（前端路由接管）。
6. 落盘 `/tmp/ms4-smoke/status/plans.json` = **2 空格 pretty-print**，含 `version/rev/plans`。
7. WS：`hello` 后 curl PUT → 收到 `plan.changed`，**cause "put"**；
   编辑器改写 `status/plans.json` → ~1.5s 内收到 `plan.changed`，**cause "external"**。
   （随后 ~1.5s watcher 还会对自己这次 PUT **复触发**一条 `cause "external"` 的
   `plan.changed`——server 自写复触发的既有行为，见 §12-2；逐字照做看到 2 条属正常。）
8. `status/plans.json` 写入损坏内容（`{ not json`）→ `GET /api/plans` 返回 **500**；
   删除该文件 → 恢复 `{"version":1,"rev":0,"plans":[]}`。

## 2. 计划 CRUD（PlanModal 新建/编辑复用、删除二次确认）

**2a. 新建计划**

**做什么：** 空态点"新建第一个研究计划"（或侧栏"研究计划"行尾 +）。
弹窗里：先不输任何东西看按钮 → 填名称"误差分析"、截止选日期、描述可留空、图标默认 target
（可点选其他 7 个之一）→ "创建计划"。

**应该发生：**

1. 弹窗标题"新建研究计划"；**名称与截止都填了"创建计划"才可点**（缺任一为禁用态）；
2. 创建后：侧栏计划列表出现该项（图标 + 名称 + 子文案 `暂无任务 · M月D日` + 进度环 0%），
   且**自动选中**——主区计划头显示名称 + 进度环 + `截止 M月D日`；
3. 主区列表区提示"暂无任务 — 点击右上角「新建任务」创建第一项。"；
4. 磁盘上 `status/plans.json` 出现（已预实测落盘格式，§0c-6）；**F5 刷新后计划仍在**。

**2b. 编辑计划（弹窗预填）**

**做什么：** 计划头右侧铅笔（title"编辑计划"）→ 改名称、改截止、换图标 → "保存"。

**应该发生：** 弹窗标题"编辑计划"，**打开即预填**当前名称/截止/描述/图标（选中态高亮）；
保存后计划头与侧栏同步更新，任务列表内容不变（若有任务）。

**2c. 删除计划（二次确认）**

**做什么：** 先建第二个计划，里面留 2 个未完成任务 + 1 个已完成任务（建法见 §3），
回到该计划点计划头垃圾桶（title"删除计划"）。

**应该发生：**

1. 弹窗标题"删除计划"，警告文案："确定删除计划「××」吗？ 其中还有 **2** 项未完成的任务，
   将一并删除。此操作不可撤销。"（数量只计未 done；无未完成任务时显示"该计划目前没有未完成的任务。"）；
2. "确认删除"后计划从侧栏消失；删的是最后一个计划时回到 §1 的引导空态；
3. F5 后不复活。

**2d. 进度展示**

**应该发生：** 侧栏每个计划项的子文案随任务状态变化：`N 项未完成 · M月D日`（todo+doing+blocked 合计），
全部完成时显示`已完成 · M月D日`；进度环 = done/total；顶部总进度条 = 各计划完成率平均。
计划头的`截止 M月D日`在 plan.due < 今天且有未完成任务时**文案变红**——与时间线条变红
同一规则（逾期未完才红，全 done 不红）。

## 4. 任务编辑与状态流转

**4a. 任务抽屉**

**做什么：** 点任务行（标题区域）→ 右侧抽屉。

**应该发生：** 抽屉自上而下 = 计划标签 + 操作组（铅笔"编辑任务" / pin / ✕"关闭"）+ 标题 +
（有 due 时 due 徽章）+ 状态四态行 + "关联文档" + "备注" + 底部"删除任务"。

**4b. TaskModal 编辑（预填）**

**做什么：** 抽屉铅笔 → 弹窗改标题、把 due 改到明天 → "保存"；再次打开，把 due 清空尝试保存。

**应该发生：** 弹窗标题"编辑任务"、**打开即预填**（标题/状态/due）；改 due 后行徽章更新；
**due 必填、不可清空**——没有"清除"按钮，把日期清空后"保存"按钮禁用（只能改成别的日期）。

**4c. 行内状态循环**

**做什么：** 点任务行首的状态圆钮，连点三次。

**应该发生：** 状态 todo → doing → done 循环（**blocked 不在循环内**）；任务随状态换组；
变成 done 后进入"已完成"组——该组**默认折叠**，点组头 chevron 展开可见，标题带删除线；
再点一次循环回 todo。

**4d. 四态直选（含 blocked）**

**做什么：** 抽屉状态行直接点"受阻"。

**应该发生：** 任务进"受阻"组；状态圆钮变红（s-blocked）；"已完成"组头计数同步。

**4d-补. blocked 的行内逃生**

**做什么：** 不开抽屉，直接在 blocked 任务的行首点状态圆钮。

**应该发生：** 任务**直接循环回"待办"**（blocked 不在 todo→doing→done 循环内，
圆钮对 blocked 的兜底就是回 todo）——受阻解除的最快路径，无需经过抽屉。

## 5. 拖拽（@dnd-kit）

**5a. 列表组内调序**

**做什么：** "待办"组放 3 个任务，把第 1 个拖到第 3 个位置。

**应该发生：** 组内顺序变为 2-3-1；F5 后保持（顺序已持久化到 tasks 数组）。

**5b. 看板跨列拖拽**

**做什么：** 看板下把"待办"列一张卡拖到"进行中"列某两张卡之间；再拖到"已完成"列空白处。

**应该发生：** 第一次 = 状态改"进行中"且落在所指两张卡之间（**跨列改状态 + 列内定位一个手势**）；
第二次 = 落在"已完成"列末尾；切回列表验证组归属一致。

**5c. 跨组拖拽拒绝（列表）**

**做什么：** 列表里把"待办"行往"进行中"组拖放。

**应该发生：** 拖动过程中**其他组变暗、光标变禁落（🛇）**；松手行回弹原位、**状态不变**，
底部浮现提示 **"跨组移动请用状态圆钮或抽屉改状态"**（约 2.5 秒自动消失）。
（跨组改状态的唯一入口是状态按钮/抽屉，设计裁决——拒绝必须可感知，不是静默回弹。）

**5d. noop 拖拽不发请求**

**做什么：** F12 → Network 过滤 `plans`，原地点按一张卡小拖几像素松手（不起实质拖放/落回原位）；
再做一次真实调序对照。

**应该发生：** 前者**没有任何 `PUT /api/plans` 请求**（同位落点在前端被短路，连请求都不发）；
后者恰好一条 PUT。

## 9. 备注 note（markdown + 数学）

**做什么：** 抽屉"备注"区点"添加备注 — 记录思路、实验观察或下一步…"，textarea 输入：

```
## 推导要点

**关键**：$a_i \cdot b_j$ 与

$$\sigma^2 = \frac{1}{n}\sum (x_i-\mu)^2$$

- 代码里用 `$a` 和 `$b` 两个变量
- 预算在 $100 到 $200 之间
```

按 **⌘↵**（Mac）/ **Ctrl↵** 保存。

**应该发生：**

1. 编辑态底部有"支持 Markdown 与数学 · ⌘↵ 保存"提示；⌘↵ 存盘回到查看态；
2. 查看态渲染：二级标题、粗体、列表正常；两个公式都是 **KaTeX 排版**（不是原始 $ 文本）；
3. **不腐蚀**：`` `$a` `` 和 `` `$b` `` 原样显示为 code（$ 没被当成公式）；
   "$100 到 $200" 原样是文本（货币不误伤）；
4. hover 查看态出现"编辑"按钮 → 回到编辑态且内容预填；Esc 放弃改动；
5. 清空内容保存 → 备注删除（回到"添加备注"空态）；任务行的 note 标记（sticky-note 图标）
   随有无备注显隐；
6. F5 后备注在。

**是 bug 的迹象：** 公式被 marked 咬坏（出现 `\cdot` 变斜体、反斜杠丢失）；code span 里的 `$`
被渲染成公式；货币段落出现 KaTeX；链接 URL 里的 `$` 被注入公式 HTML（可另试
`[x](https://a.com/?q=$x$)`——应渲染成普通链接，href 原样含 `$x$`）。

## 11. 持久化与同步

**11a. F5 持久化**

**应该发生：** 任何增删改之后 F5，界面状态完整恢复（数据在服务端 `status/plans.json`，
已预实测 2 空格 pretty-print 落盘，§0c-6）。

**11b. 外部改写免 F5（agent/CLI 协作语义）**

**做什么：** 前端停在计划页，用编辑器修改 `status/plans.json`（如改一个任务标题）保存。

**应该发生：** **~1.5s 内前端自动更新**，不重载页面（watcher 指纹 → `plan.changed` external 广播，
已预实测广播序列 `hello → plan.changed(external)`，§0c-7）。同样地，另一终端 PUT API 后
所有打开的标签页自动重取。

**11c. 多窗格自动刷新（per-pane 实例独立）**

**做什么：** ⌘\\ 开第二个窗格，两边都切到计划页；窗格 A 改一个任务的状态。

**应该发生：** 窗格 B **几乎立即**（WS `plan.changed` 广播）自动重取、显示新状态；
~1.5s 后 watcher 对自己 PUT 的复触发会让两边再做一次幂等重取（§12-2）。
每个窗格的计划页实例独立（选中计划/列表模式/回声抑制互不影响）：B 正在做的编辑
不会被 A 的广播打断——B 若有在飞写入，回声抑制跳过该次重取，以 B 自己的 PUT 响应为准。

**11d. 乐观锁 409（双窗格/双标签）**

API 层已预实测：过期 rev → 409 并回传当前 rev（§0c-3）。UI 复现手法：

**做什么（确定性路径）：** 开两个标签页都进计划页。在标签 B 里：

1. F12 打开 DevTools → **Network** 面板 → 顶部过滤器选 **"WS"**；
2. 如果列表是空的（/ws 在面板打开前已建立），**保持面板打开并刷新页面**；
3. 列表里 `/ws` 那行**右键 → "Block request URL"**（也可以在 Network 的
   **Blocking** 子标签里手动添加 `*/ws`）；
4. 刷新 B——B 照常可用但收不到任何广播。

然后 A 改一个任务标题；B 改另一个任务标题。

**应该发生：** B 的写入因 rev 过期被拒 → 底部提示 **"计划数据已被其他来源更新，已重新载入"**，
随后 B 自动重取（A 的改动出现在 B 里，B 自己那次编辑被回滚）。
（不修 WS 的朴素双窗格连点也能撞上 409，但 WS 通常先帮 B 同步到新 rev——B 直接写入成功，
这**不是** bug。）

**11e. 加载失败态**

**做什么（确定性路径）：** server 跑着，往 `status/plans.json` 写入损坏内容
（`printf '{ not json' > status/plans.json`），刷新页面；然后删除该文件，点"重试"。

**应该发生：** `plans.json` 损坏时 `GET /api/plans` 返回 500（已预实测，文件删除后恢复空文档），
页面显示显式失败态"无法连接服务器 / 计划数据暂时不可用 — 确认 serve 正在运行后重试。/ 重试"
（**不是**空计划态——"读不到"不伪装成"没有计划"）；删除文件后点"重试"→ 回到引导空态。
（注意边界：整个 server 停止后再刷新是浏览器级"无法连接此网站"——SPA 本身加载不了，
不在这个状态的覆盖范围；它覆盖的是"SPA 已加载但 /api/plans 取数失败"：文件损坏 500、
或页面打开后服务才中断且尚无数据。）

## 12. 已知限制与清理

**已知限制（验收时别当 bug 报）：**

1. **tab 关闭时若有在飞的写请求**，最后一跳可能未落盘（写链在内存，单用户可接受，
   下次打开自动以磁盘为准）；
2. 自己 PUT 后 watcher 会**再广播一次** `plan.changed`（server 自写复触发，既有行为，
   前端重取幂等无害）；
3. 时间线只读（无拖条改期）；任务不跨计划移动；跨组改状态走状态按钮/抽屉，不走拖拽；
4. 任务抽屉的链接只有 `doc_id` 一级（无 anchor 深链，Stage 4.1 再议）；
5. 编辑计划/任务弹窗不含 note/links/focused（分别在抽屉/行内操作，设计裁决）；
6. 今日聚焦卡片上的状态圆钮**不可点**（pointer-events 关闭，整卡点击 = 开抽屉）——不是失效；
7. 写失败（非 409 冲突，如网络中断）的提示文案是 **"保存失败，已重新载入"**
   （§11c 的冲突文案是"计划数据已被其他来源更新，已重新载入"——两种文案对应两条路径）；
8. 撤销 toast 会被**第二次删除替换**——只有最近一次删除可撤销（toast 单例，
   6 秒窗口随新删除重置）；
9. **Stage 4 smoke 前创建的无 due 任务**，载入时自动补为所属计划的 due（一次性迁移，
   不改 rev、不立即落盘，下次保存时落盘）——旧文件不会报 schema 错。

**清理（把状态恢复原样）：**

```bash
rm -f status/plans.json        # 情形 B（repo 根）；status/ 空目录可一并删
rm -rf /tmp/ms4-smoke          # 情形 A
```

`plans.json` 删除后下次 GET 返回空文档 `{"version":1,"rev":0,"plans":[]}`，前端回到引导空态
（已预实测 §0c-1）。

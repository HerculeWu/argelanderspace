# Copilot 与用户共享 UI 能力和页面上下文

工作台向 Copilot 提供能力和上下文，具体任务由用户决定。用户能在 UI 上完成的操作，Copilot 也能完成；UI 没有的操作，Copilot 也不能做。由此按 UI 能力设计接入，不预先将助手限定为文献问答、只读检索或只能生成修改草稿的任务集合。

## Consequences

- 页面上下文传递结构化表示，不使用界面截图。每次发送提供当前活动面板、对象及页面内可滚动阅读的完整内容，附当前阅读位置和选区作为定位提示。内容范围不受当前屏幕、已挂载 DOM 或可见 PDF 页限制；当前页面的筛选和对象范围仍成立，不能据此扩成整个工作台的全部数据。具体编码、版本、更新协议及超出模型输入容量时的处理仍需设计。
- 能力对等按业务操作定义。Copilot 可以在后台读取和修改用户可经 UI 操作、但尚未打开的对象；读取和修改不强制跳页，打开、切换和定位操作才驱动可见页面，修改结果正常同步到 UI。
- 用户让 Copilot 处理 A 后切换到 B，Copilot 继续处理 A；当前页面与任务对象分别记录，切页本身不改变任务目标。
- 用户与 Copilot 同时编辑时，发现内容已变化便重新读取最新内容，再决定后续修改；不能用已过期的副本覆盖用户的新编辑。具体冲突检测与提交机制仍需设计。
- 对话独立持久保存，切页面继续同一会话；新建和切换对话由用户决定。已有消息保留发送时的上下文定位，不能随当前页面变化改写引用对象。
- 原 UI 要求用户确认的操作，由 Copilot 展示同一确认流程并等待用户确认；普通保存、计划编辑等依用户任务直接执行，不增加统一的写入审批模式。
- 本地服务仍在时，收起侧栏、切页、刷新或关闭网页不停止已提交任务。显式停止后不启动新步骤，已提交的写入安全收尾并报告结果；服务退出后任务记为中断，重启由用户决定继续，不自动重放结果未明的写操作。
- 新能力要同时考虑用户的 UI 入口和 agent 的操作入口；仅有内部函数、文件路径或旧 CLI 命令，不自动成为 Copilot 可执行的操作。
- 数据保护仍遵循 [完整契约](../contracts.md)。具体操作对应关系、确认 UI 和工具传输方式仍需设计，不能用本决定推导绕过校验或开放任意文件/进程权限。
- 本决定规定新增 Copilot 的设计方向，不宣称能力已经实现，也不改动既有外部 CLI 的冻结输出。Codex/Claude Code plugin 的设计与实施不在本轮范围。

来源：2026-10-02 Copilot 设计访谈，用户对第一轮 Q1–Q3 的明确答复。将来的具体任务类型不构成收窄或扩大本能力边界的理由。

2026-10-02 第二轮 Q9–Q10：用户接受后台业务操作与可见导航分开、跨页面持久会话及逐消息上下文定位；补齐本 ADR 原先未定的对应范围，其余未知项未自动批准。

2026-10-02 第三轮 Q13–Q14：用户接受原 UI 的人工确认语义和后台运行、停止、中断恢复规则。随后澄清的文本源保存与 Reader 更新方式（Q11）见 [ADR 0006](0006-text-input-to-shared-ir.md)。

2026-10-02 第四轮 Q15–Q17：用户确定切页后继续原任务、编辑冲突重新读取，并要求滚动页面直接提供完整内容。该新决定覆盖第二轮 Q10 中“当前可见范围＋全文按需读取”的默认上下文范围，因为用户希望 agent 直接看到同一页面中可滚动阅读的全部内容；不改变会话持久化、逐消息对象定位或 UI 能力边界。PDF 原页作为多模态材料的决定见 [ADR 0006](0006-text-input-to-shared-ir.md)。

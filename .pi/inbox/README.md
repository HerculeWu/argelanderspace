# Inbox：session 增量与归并协议

状态：已批准。来源：2026-09-13 用户与 agent 三轮 grilling，Q1–Q19 全部按推荐确认，随后明确授权本次实施。规则适用于本项目全部开发 session，不绑定特定 harness。

## 1. 分层与启动

所有记忆相关材料只放 `.pi/`：

- `../memory/`：精简正式记忆，启动完整读取，先 `00-index.md` 再按索引顺序。
- 本目录：尚未归并的有效增量；本协议及全部 session 文件启动完整读取，按记录的事件时间理解先后。
- `../memory-reference/`：专题细节、获授权的阶段方案、整理审计材料，按任务读取；关键硬约束必须在正式记忆中有摘要和入口。

Inbox 不是低权威草稿箱：已确认的新决策即使尚未归并也生效。目录位置不决定权威。全部读取后才能开始工作；超阈值也不得截断或跳读。

每条现行知识只有一个权威位置，其余通过链接引用。摘要可以重复必要的安全提示，但不能维护另一套完整规则。

## 2. 日常写入

- 日常默认只写自己的 session inbox，不顺手重写正式记忆、专题或其他 session 的记录。用户明确授权的即时更新或专门整理例外。
- 一个 session 默认一份 `YYYY-MM-DD-<session短标识>-<主题>.md`；短标识用于避免同日同题撞名，不要求特定工具生成。同 session 跨日继续更新原文件。
- 出现已拍板决定、新验证、重要问题或阻塞时及时创建/更新，结束前收尾；不是等 session 结束才从头补写。
- 没有长期价值或交接需要的 session 不强制建空文件。不要复制工具流水账或完整对话。
- 记录头部时间使用带时区的 ISO 时间；历史事件只知日期时照实写日期并注明精度，不能编造时间来排列决策。
- 中断也须能区分完成与未完成、决定与建议。工作状态和归并状态分开；“工作完成”不等于“已归并”。

### 轻量模板（Markdown，不引入解析器）

```markdown
# <主题>
- Session：<短标识>
- 创建：<带时区 ISO 时间>
- 更新：<带时区 ISO 时间>
- 工作状态：进行中 / 完成 / 中断 / 阻塞
- 归并状态：未归并 / 部分归并
- 范围与授权：<此次可以做什么，不能做什么>

## 已确认决策
### D1 — <题目>
- 决策时间与来源：<用户明确确认，或授权范围内的 agent 技术决定>
- 结论、理由、范围：...
- 覆盖：<旧文件及条目 → 新规则；全部替代 / 局部修订 / 无>
- 重新讨论条件：<有则写；没有则省略>

## 已验证事实
### F1 — <题目>
- 观测时间与环境：...
- 结论与证据：<可定位路径/测试/提交；临时证据须标记>

## 问题变化
### I1 — <题目>
- 开放 / 接受的边界 / 推后能力 / 待确认 / 已解决：...
- 影响、证据与下一步：...
- 已有问题编号：<有则沿用>

## 待确认事项
### Q1 — <尚不能视作决定的事项>
...

## 交接状态
- 已完成、未完成、阻塞、相关 diff/分支/提交状态。
- 归并去向：<专门整理时填写条目 → 正式记忆/专题/历史/继续待确认>
```

空分节可省略；`D1/F1/I1/Q1` 在本文件内稳定，不复用删除条目的编号。跨文件引用“文件名 + 条目号”，无需全局决策注册表。正式问题清单的稳定编号见 [known-issues](../memory/known-issues.md)。

## 3. 权威与冲突：新决策覆盖旧决策

**同事项、同适用范围内，有权作出的新决策覆盖旧决策。** 按决策发生时间，不按文件名、mtime、写入或归并时间判断。

- 用户明确决定可以改变产品定位、范围和约束，包括本次对话中尚未写盘的新决定。
- Agent 只能在明确授权范围内作技术决定，须记录授权背景；不能越权推翻用户约束。
- 审查建议、探索提案、假设、重复转述不是新决策；代码实际行为与决定不符先记为实现偏差，不能凭实现较晚自动覆盖。
- 新条目须写“旧条目定位 → 新结论 → 覆盖范围 → 原因”；局部修订不自动废除其余约束。
- 来源、时间、范围或是否拍板不清时，保留现行规则并标记冲突。影响当前工作的部分先问用户，不猜测，不以含糊措辞扩大授权或取消数据保护。
- 决策与事实分开：事实按观测时间、证据及环境更新。新证据明确推翻旧结论才标记取代；不同环境可各自成立。临时证据丢失不自动推翻已有验证，不重跑所有历史实验。
- 阶段执行授权随阶段结束失效；长期产品/数据/接口契约继续有效，直到被合法新决策取代。难辨临时限制与长期契约时列待确认。

## 4. 专门整理

只在用户授权的整理任务中归并。一次授权允许机械、无争议的去重、更新状态、应用明确的新决策和修复引用，不需要逐条请批。来源/覆盖有歧义、压缩可能损失关键理由、或需要创造新规则时再询问。

逐条处理：

1. 长期有效 → 正式记忆或专题；保留结论、关键理由、适用范围、重新讨论条件（有则记）。
2. 新决策覆盖旧条目 → 权威位置只留现行规则与必要的一句替代说明；关键决定保留日期及来源。
3. 临时过程 → 丢弃或压入历史摘要，完整原文由 Git 保留。
4. 待确认 → 留 inbox，不以“清空”为由强行定论或丢弃。

**裁剪或删除 inbox/旧记忆原文前，必须确认原文已经有可定位的持久 Git 记录。** 未提交内容不能仅因摘要已写就删除；无 commit 授权则保留原文并注明哪些条目已归并，等待后续授权。不能假定重命名或存在工作区就等于已有历史。

部分归并时，记录条目去向及原文提交，移除已吸收内容，文件头注明“部分归并”，只留下未决内容及必要上下文。全部处理后删活动 inbox 文件，避免下次重复读取；删除前仍遵守原文入 Git 条件。同步更新指向旧文件/条目的引用：现行规则链接改指新权威位置，原始决策来源改用持久提交定位，不留断链。

整理报告列出更新、替代、剩余未决事项及保真核对。**整理授权不包含 Git commit/push 授权**，不得从旧阶段继承。正式资料的参考预算约 35–50 KB，不为达标牺牲关键知识。

## 5. 阶段方案与历史

获用户授权形成的长篇方案放 `../memory-reference/`，标注草案/已批准/执行中/已关闭；正式记忆或 inbox 给入口。草案不是有效决定。日常执行进展仍写 inbox，不把方案变为审查流水账；修改方案须有相应授权。

阶段关闭后的专门整理提炼有效结论，详细执行方案退出活动资料，原文入 Git；产品否决理由、长期契约不能随阶段过程一起丢掉。

## 6. 提醒、证据与敏感信息

- 启动/收尾时检查：未归并 session 文件（不含本 README）达到 **8 份**，或正文 UTF-8 字节合计达到 **40 KB（40,000 字节）**，提醒安排整理；阶段关闭或开始新阶段前也提醒一次。阈值是软提醒，不自动整理、不跳读。
- 关键结论自包含，优先引用持久测试、源码、提交；`/tmp` 日志/截图/副本只能当临时证据，不承诺以后可访问。
- 可记录凭据位置、配置方法；不记录 token、密码、完整敏感日志。Inbox、专题、审计材料同样遵守。
- 本版仅文档协议，无插件、hook、后台任务或自动归并。允许一次性只读统计与链接检查；实际需要再单独讨论自动化。

## 模块地图（packages/server/src/）

- `app.ts` — `createApp(deps)`：8 端点 + images + SPA。deps 注入 `{paths, makeSources(offline), pipelines, runner, broadcast, webDist, port}`，测试全打桩、零网络。
- `jobs.ts` — `JobRunner`：FIFO promise 链串行；`<dataDir>/jobs/<id>.json` 每次跃迁原子落盘（tmp+rename）；boot 时 queued/running → `interrupted`（绝不重跑），并清理 `jobs/spool/` 残留。`waitFor(id)` 支持**多等待者**（修过的坑：端点的 `library.changed` 钩子 + 测试同时 await 同一 job，单 waiter Map 会被覆盖丢事件）。
- `lock.ts` — `AsyncLock`（promise 链互斥）= Python `_WRITE_LOCK`：只包 rebuild 的 load→save 和 PATCH/POST refs 端点，**不包 OCR**（Python 语义：OCR 期间 patch 不等）。
- `paper-cache.ts` — mtime+size LRU(16)。坑：**`statSync().mtimeNs` 不存在于普通 stats，必须 `statSync(p, {bigint:true})`**。
- `ws.ts` — `WsHub`：`ws` 库 `noServer` + upgrade 监听（非 `/ws` 路径 destroy）；连接即发 `hello`（job 表快照）；协议级 ping/pong 心跳 30s。
- `deps.ts` — 组合根：`realSources(paths, offline)`（cache 子目录 ads/crossref/openalex 同 Python；**offline 只禁 Crossref/OpenAlex，ADS 恒活**——bug-for-bug）、`realPipelines(paths)`（outRoot 指向 `<dataDir>/output`）。
- `server.ts` — `createServer({dataDir, port, webDist, deps?, heartbeatMs?})` + `startServer` + `resolveServerConfig`（`--data-dir` > `ARGELANDERSPACE_DATA_DIR` > `./data`；port 同构默认 8000；web-dist 自动找 `packages/web/dist` → `web/dist`）。

## 端点 parity 与有意分歧（详见 app.ts 头注释）

逐端点对齐 `server/app.py`（状态码 + `{"detail": ...}` 形状 + repr 单引号消息）。**大声标记的分歧**：

1. **upload 默认异步**：`POST /api/library/upload` → `202 {"job": {...}}` 立即返回，PDF spool 到 `<dataDir>/jobs/spool/<jobId>.pdf`，OCR 作为 upload job 串行跑；`?sync=1` 保留旧的同步 `{ref}`/404/500 行为（已测）。M5 前端走 async + WS。
2. refresh 响应形状不变（同步等 summary），但 rebuild 在 runner 里跑（WS 可见 progress；与 upload 互斥）。
3. CSRF allowlist 加了**服务器自身端口**的 localhost/127.0.0.1（否则非 8000 端口下同源 SPA POST 全被 403）。
4. `?offline=banana` 这类非法布尔 → `422 {"detail": string}`（FastAPI 是 422 但 detail 为数组）。
5. SPA fallback：未知非 API GET 路径回 index.html（Starlette StaticFiles 原本 404）——客户端路由需要。
6. `..`/`%2e%2e` 路径段在 WHATWG URL 层就被归一化掉了，到不了 handler（FastAPI 里会 400）；无安全问题，guard 仍挡 `.hidden`、`a%2Fb` 等。
7. refresh 失败 → `500 {"detail": <err msg>}`（FastAPI 未捕获异常是纯文本 "Internal Server Error"）。

## WS / job schema（contracts/src/jobs.ts，zod）

- `Job`：`{id: "<kind>-<uuid>", kind: upload|refresh|ingest, status: queued|running|done|failed|interrupted, createdAt/startedAt/finishedAt(ISO|null), progress: [{at, message}], result, error, payload?}`——落盘 JSON、202 body、WS 负载同一形状。
- WS server→client 消息：`hello{jobs[]}`（连接快照）/ `job.created|progress|done|failed {job}` / `library.changed {cause: refresh|patch|add|upload, at}`。**wire 顺序保证 job.done 先于 library.changed**（runner 先 emit done 再 resolve waiters）。
- upload 202：`{"job": Job}`（`UploadAcceptedResponseSchema`）。

## 组合层决策

- **job runner 放 server-local 而非 core**：它是 HTTP/WS 层的执行编排（队列/进度/广播），无领域逻辑；core 保持纯领域。M5 CLI 若需要可依赖 server 包或届时再提升。
- core `attachPdf` 加了可选 `rebuild` 注入缝（server 传入 lock 包裹版）——这是本里程碑对 core 的唯一改动。
- planner 活注册表：`lockedRebuild` 统一传 `htmlAdapterInfos()`（兑现 m3c 笔记的"M5 组合层"约定，server 先接了）。
- 测试夹具：运行时拼 `<tmp>/data`（golden `arxiv-2501.17225.json` + core 的 `library.json` + 单节点 graph.json + 伪图片 + 伪 SPA dist），stub sources/pipelines；WS 测试用真 socket 临时端口。

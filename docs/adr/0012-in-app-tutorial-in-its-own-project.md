# 应用内教程在独立的教程 Project 里运行

工作台内置一份分步教程（[CONTEXT](../../CONTEXT.md#教程)「教程」）。它只在由随包教程示例复制出来的教程 Project 里运行，永远不挂载到用户自己的 Project；教程层自己不发外部请求、不调用模型，对产品的唯一主动操作是导航，观察只经现有状态源；Copilot 章只回放制作示例时真实跑过一次的会话。教程进度属于人，存全局数据目录（[ADR 0007](0007-global-data-scope.md)），不存项目目录。用户在教程里做的产品操作照常生效：第 2 章上传源码包摄入后，产品照常联网补全元数据；第 4 章的文献探索要用户自己的 ADS token（见下文「撤回的决定」）。

## Considered Options

- **在用户自己的 Project 里运行教程**：门控步骤要写标注、论证、任务、稿件，会改动用户数据，与数据保护契约冲突；用户也无法随手重来。否决。
- **教程自己联网**（真实 Copilot 往返、由教程替用户发探索请求）：要 provider key 与 ADS token 才能走完，花 token，结果不可复现，文案无法写「你会看到什么」。否决；Copilot 章改为回放预置会话，第 8 章没有前置条件。
- **进度存教程 Project 内**：换文件夹即丢，与「属于人的放全局」（ADR 0007）相悖。否决。
- **示例随每个发布版本自动重生成**：每次发版都要 TeX 与网络，产生无意义的 IR / SVG diff，重摄入还会让预置标注的指纹失效、用户第一眼就看到归档。否决，改为冻结产物加回归守护（下文）。
- **示例版本与产品不一致时拒绝继续，或不提示让产品自己报错**：教程 Project 是用户的 Project，里面有用户写的东西，不能替用户决定删；不提示则用户撞上读取错误不知原因。都否决，改为只提示不拦。
- **用 app 版本号或内容 hash 判断示例是否过旧**：app 版本每次发版都会误判老用户；hash 的范围难定且不可读。否决，改用只在重生成时递增的示例序号。
- **随包带更多论文的正文**（Meingast & Alves 2019、Pflamm-Altenburg 2023 等的 IR 与图）：前者是 arXiv 非独占许可，后者是 CC BY-NC-ND（IR / SVG 按保守读法属于改编）。否决，见「示例数据的许可边界」。
- **构建时生成示例**：要 TeX、网络与 token，且与冻结产物矛盾。否决。

## Consequences

### 示例是冻结产物，由回归守护

- 仓库根 `tutorial-sample/` 是**提交入库的冻结产物**，桌面包与 npm 包都原样带一份（定位与打包见 [architecture](../architecture.md#教程进度与-apitutorialin-app-tutorial-票-18)）。标注、论证图、Plan、稿件等手写内容以固定 id 的 JSON 文件进示例——产品里这些 id 是随机生成的，不能经 API 产出；教程定义引用的示例 id 是常量，web 包的守护测试逐个到示例里找。
- 四门里的「示例可加载」回归是教程可用级的不变量：正文 IR 能读，预置标注经一次 ensure 不产生归档，论证图审计恰好一条故意留下的发现，Plan 与稿件能读，预置 Copilot 会话能读回（三问、两张操作卡、无确认卡），示例不含任何 ADS 数据，库图恰是五篇之间真实的 9 条引用边。格式、键或第三方会话格式一变，测试先红，而不是用户先看到错误。
- 生成脚本（`regenerate` 重摄入钉死版本的 e-print 并重算标注指纹，`assets` 重打上传用的 zip）是回归红了才跑的**修复动作**，不随发布自动跑；任一核对失败整体不写。预置 Copilot 会话与 Pi session 文件只靠可加载回归，格式变了才重录，不在示例里记 Pi 版本（每次无害升级都会假警报，而重录要 provider 与真实 token，是最贵的修复）。做法见 [engineering](../engineering.md#教程示例in-app-tutorial)。
- 示例根的教程标记带一个只在脚本成功时递增的整数序号；手工微调不递增，不与 app 版本比较。用户已有教程 Project 的序号与随包示例不同时，入口与 `argelanderspace tutorial` 只提示（并给出重新开始的路），照常加载；**任何情况下都不在读取代码里为教程放宽契约**。
- 发布前的包冒烟再核一次「包里的示例能被真实 server 加载、不产生归档」，守四门看不见的打包环节。目前只有发布工作流的 Linux 桌面包冒烟跑这一项，macOS / Windows 没有对应核对（见 [engineering](../engineering.md#发布工作流desktop-app-票-26)）。

### 示例数据的许可边界

- 随包正文只有 Jerabkova 等 2021：依据其 arXiv v1 的 CC BY 4.0，带摄入产物（IR 与图转换出的 SVG），须署名、给许可链接并说明「由 LaTeX 源码与图转换而来」。
- Röser 等 2019、Meingast & Alves 2019、Pflamm-Altenburg 等 2023、Kroupa 等 2022 只带书目元数据；摘要用 arXiv 版本（arXiv 元数据为 CC0），不随附出版社文本。
- Evans & Oh 2022 的 arXiv e-print（v1，CC BY-NC-ND 4.0）原样转成 zip 随附，供第 2 章现场上传——文件逐字节不改，只换容器，不随附它的摄入产物；zip 不在本软件的 MIT 许可之内，仍只按 CC BY-NC-ND 使用。主 `.tex` 文件头保留的 MNRAS 模板版权注释（RAS，`mnras` 包 LPPL 1.3）原样保留。
- 不再分发任何取自 ADS API 的数据（下节）；书目记录里的 bibcode 来自 ADS 核实，`NOTICE.md` 致谢 ADS 并附条款链接。
- 示例根的 `NOTICE.md`（英文）逐篇列题目、作者、arXiv 链接、DOI、许可，写明示例取自 arXiv 版本、仅供教程演示。
- 代价：两篇以上论文没有正文可读，阅读、论证图与任务关联都只用 Jerabkova；换来的是示例能随开源软件分发而不需要另行申请许可。

### 撤回的决定：随包的离线探索缓存

- **原决定**（2026-10-21，票 14，用户「都按推荐」）：示例随附 Röser 等 2019 为起点的三条 ADS 探索响应缓存（seed、similar、useful），条目带 `pinned: true` 不过期，产品从不写它、只由生成脚本写；之后又按出版社版权剥掉其中的摘要。目的是第 4 章不要 token、不联网也能出探索结果。
- **撤回**（2026-10-21 同日，用户裁决）：许可核实读到 ADS 现行 API 条款第 2 条——不应把取自其服务的数据再分发给第三方——且对书目字段或少量缓存没有例外。示例因此**不再随附 ADS 探索缓存**；生成脚本的 `cache` 子命令与 infra 的 pinned 条目一并撤回（它们只有这一个写入者），[discovery](../discovery.md#ads-discovery-缓存) 的缓存节回到原文（「无 stale-while-revalidate……」一句原本就没动）；npm 包与桌面包的组装检查拒绝示例里出现 `literatures/library/cache`。
- **现状**：第 4 章的探索要用户自己在设置里填的 ADS token；没有 token 时探索页显示产品自己的错误态，相关门控步走「跳过这一步」。教程框架不加「需要 ADS token」标记，教程定义不依赖任何固定的探索结果；产品 UI 不为教程加字段。
- **否决的替代**：进入教程时刷新缓存时间（非入口方式进入不刷新，第二天即失效）；无 token 时读过期缓存（改变所有项目的语义）；把时间写成未来（靠漏洞）；用 arXiv / OpenAlex 等 CC0 数据重建假数据（「相关」与「方法基础」的结果只能来自 ADS，假数据不是产品真实会看到的画面）。
- **重新讨论的条件**：取得 ADS 的书面再分发许可（联系方式见其条款），或 ADS 条款改为允许；届时可恢复不过期条目与生成脚本的 `cache` 子命令（实现与测试在 Git 历史里）。

### 其他

- 教程对产品的唯一主动操作是导航（调用已注册的视图动作）：不模拟点击、不自动跳转、不写项目数据、不向输入框写值；要打字的步骤给准备好的文字和复制按钮。观察只经现有状态源（与 Copilot 看到的是同一份页面上下文，[ADR 0005](0005-copilot-ui-parity.md)），`GET/PUT /api/tutorial` 是观察层唯一新增的路由；桌面入口另有三个宿主接口。硬契约见 [contracts](../contracts.md)「教程进度与教程 Project」。
- **教程讲文献仓，写进用户真实的文献仓**（2026-10-24）：第 2 章引导用户把 Jerabkova 加入文献仓（[ADR 0013](0013-shelf-copy-not-global-library.md)）。文献仓是属于人的全局数据，这一写入不在教程 Project 里，重新开始教程不清除它；它是用户自己的产品操作，与第 2 章联网补全、第 4 章用自己的 ADS token 同理，卡片明说会进你自己的文献仓。教程 Project 里文献仓的入口、「文献仓已有」提示与 Copilot 工具与普通 Project 相同，不为教程另设判断。用户文献仓已有同一篇时，产品照常出整条替换确认，卡片提示取消并跳过这一步。否决：教程专用的文献仓（要为教程开产品分支、把全局数据切出一块，违背本决定「不为教程放宽契约、不加字段」）；只看不写（学不到真正的加入）。这推翻文献仓设计访谈 Q21「教程 Project 中隐藏文献仓全部入口，教程不讲」，契约同日局部修订。
- TeX 是唯一可选的本地前置；没有它的步骤标「需要 TeX」、可跳过，不承诺预置的替代结果（示例不带渲染缓存）。
- 教程卡片是「UI 不负责解释和教学」原则（[engineering](../engineering.md#前端交互规范)）的明文例外，例外只覆盖教程层自己的卡片，不许借教程名义往产品界面常驻说明。
- 示例很大（约 70 MB，绝大部分是 Jerabkova 的 19 张 SVG，原样接受；示例原始体积上限 100 MB，deb 增量上限 20 MB——原定 15 MB，实测 Tauri 的 deb 用 gzip、增量 17.0 MB，用户裁决放宽）。仓库因此变大，没有用 LFS。

## 重新讨论的条件

- ADS 书面许可或条款变化：见上文「撤回的决定」。
- 其余论文的作者或出版社给出书面再分发许可：可把对应正文加回示例。
- 有人要在用户自己的 Project 里跑教程：须先重新设计数据保护，本决定不支持。
- 示例超出体积预算：回到体积预算的取舍（栅格化图、压缩、LFS 都曾被否决）。

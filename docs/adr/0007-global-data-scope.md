# 引入用户级全局数据，与项目数据并存

此前所有数据都在项目级 dataDir（按 cwd 解析、不向上查找），契约也写明全局库复用没有实施授权。邮箱账户属于用户本人而非某个研究项目：同一人在两个项目目录各开工作台，应看到同一组邮箱。因此正式引入**全局数据**，规则是“属于人的放全局，属于研究项目的放项目”。今后需要跨项目共享的数据都归入全局数据，不再逐项另立位置。

## Considered Options

- 每个项目各自配置邮箱：用户要在每个项目重复添加账户与凭据，凭据副本随项目目录扩散。
- 跟随 dataDir 但建议只用一个项目：把属于人的数据绑在偶然选中的项目上，换目录即“丢失”邮箱。

## Consequences

- 全局数据与全局缓存分开：全局数据丢失需要用户重新配置；全局缓存是可丢弃的派生数据，可随时删除重建。两者和既有配置文件都使用各操作系统的标准用户目录，并提供与 dataDir 对称的显式覆盖；具体路径见 [architecture](../architecture.md#数据与配置)。
- Library、标注、Plan、Manuscript 等既有项目数据**不迁移**，项目数据的解析规则不变。本决定不授权全局 Library 复用；某类既有数据若要改为全局，须另行决定并按契约先备份、说明回滚、取得授权。
- 多个工作台进程会共享同一份全局数据，因此每种全局数据必须说明自己的跨进程并发范围，不能默认沿用项目数据“跨进程并发不支持”的边界，也不能把它推广到项目数据。邮件的范围见 [contracts](../contracts.md)。
- 全局数据可能包含凭据或个人通信，不进入公开仓库、文档或票据。

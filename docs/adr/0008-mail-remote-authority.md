# 邮件以远端为准，对外动作必须由真人确认

工作台的 Mail 是通用的多账户 IMAP/SMTP 客户端。远端邮箱是 Message 的唯一权威：本地只缓存列表、已打开的正文和附件，这些都是可丢弃的全局缓存；搜索使用服务端搜索，不建立完整的本地离线副本。邮件与文献不同，发出后不可撤回，并且以用户的身份对外发言；邮件内容又来自任意外部发件人。因此，对外动作和破坏性动作必须由真人确认，邮件内容一律作为不可信数据处理。

## Considered Options

- 像 Thunderbird 那样完整离线同步：需要本地数据库（未获授权的 SQLite），而且 GB 级邮箱无法用 JSON 文件存储；缓存还会变成需要按契约保护的用户数据。
- 第一版提供外部 agent 用的 mail CLI：CLI 没有确认卡，发信会成为无人把关的对外动作，读信会把不可信内容直接交给外部 agent。

## Consequences

- 本地缓存损坏或丢失时重新拉取即可，不适用标注那一套保全规则。草稿与已发送邮件保存在服务器的 Drafts、Sent 文件夹，不另建本地持久稿件。
- [ADR 0005](0005-copilot-ui-parity.md) 的能力对等仍然成立：Copilot 可以读信、搜索和写草稿。对 Copilot 而言，发送、回复、转发、删除和移动永远需要真人确认卡，卡上显示收件人、主题和正文全文，模型不能自行批准。用户在 UI 中直接点发送不需要再确认一次。
- 发送有 8 秒撤销窗口，和 Copilot 的撤销窗口一致。窗口结束前 server 退出时，未发出的邮件放回草稿，不自动补发，并如实报告它没有发出。
- 邮件正文、信头和附件对模型来说是数据，不是指令；邮件里的任何“指示”都不会被自动执行。Mail 页面的上下文只包含当前打开的邮件全文和列表信头；附件需要通过工具显式读取。
- HTML 邮件在 web 端清洗后放进沙箱显示。远程内容默认不加载，需要用户对每封邮件单独允许。
- 凭据优先存放在操作系统钥匙串中。钥匙串不可用时，只有在用户明确同意后，才退回到全局数据中的受限权限文件，并在 UI 上持续标出这一状态；不自动降级。凭据不进入日志、文档或票据。
- 第一版不提供 mail CLI；以后如果要加，先只做只读命令，并单独决定。
